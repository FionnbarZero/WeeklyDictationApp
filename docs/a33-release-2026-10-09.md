## Resolved score-policy mismatch

Read-only inspection of the previous production ruleset `projects/weeklydictationapp/rulesets/a69cfc5b-abdd-4eb2-81ce-9ecdf129cd72` (release updated October 6 at 06:32:35 UTC) confirmed that `betaResults` accepted only the original score fields. A3.3 save paths include optional `schoolYear`; that production allowlist omitted it. The candidate `firestore.rules` permitted that field, but the production-policy snapshot `deployment/firestore-family-sync.rules` did not. Earlier emulator coverage used untagged scores and missed the mismatch.

A local emulator reproduction using that production-policy snapshot confirms that an otherwise identical legacy score succeeds and an A3.3 school-year-tagged score is rejected with `PERMISSION_DENIED`. It used only disposable emulator records. Production rules and family records were not changed.

The owner explicitly approved this production security repair in chat. The tracked production snapshot now allows the optional field with validation, preserving family ownership, immutable scores, and rejection of recordings/other fields. A permanent regression runs in the existing CI production-policy job and covers all three grades and writing/reading/game channels.
